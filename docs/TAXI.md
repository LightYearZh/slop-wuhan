# 出租车接送 · 0.9.0

在自由漫游基础上增加一个小型接送循环。切换到汽车，点击左上方“开始接单”（或按T），查看订单后“接这一单”，沿地图和路面导航接客、送客，停车后完成结算。不会打开页面就自动派单。

## 如何玩

1. 使用汽车，到汉口沿江大道一带开始接单。距离服务区域过远或找不到合法道路路线时，会提示并提供前往江汉关候客区的按钮；这是接单前的正常传送，不是途中自动驾驶。
2. 查看乘客、起终点、预计里程、时间和虚拟车费，再接受订单。沿黄色路线驶向乘客，候车人在路边。
3. 距停靠点7米以内、车辆低于约4km/h、处在同一高程层，保持约1.8秒停车；随后用2秒简化步行动作上车。提前开走会退回等待停靠。
4. 按青色路线送客，再停车下客。结算显示实际行驶距离、用时、收入与当班完成单数。可以再接单，或结束接送继续漫游。

地图打开或页面进入后台时，不推进停靠/上下车时间和行程计时。切换其他载具、传送、取消本单都不会获得收入。切换方式后仍可自由漫游，不会被任务锁住。不会因为从桥上经过某个地面点或以较高车速擦边驶过就完成接送。

## 第一批路线

仅在汉口地面道路提供三条短途订单：

| 上客区 | 下客区 | 路线长度 |
| --- | --- | ---: |
| 江汉关附近 · 沿江大道 | 巴公房子附近 · 沿江大道 | 约1,057米 |
| 航运中心附近 · 沿江大道 | 汉口江滩 · 沿江大道 | 约792米 |
| 汉口江滩 · 沿江大道 | 领事馆旧址街区 · 沿江大道 | 约1,279米 |

名字表示附近路边停靠区，不是让车进入步行街、地标内部或台阶。先限定同岸，尚未开放随机跨江、桥上或地下上下客。

## 实现与参考

参考London Loop `js/rideldn.js` 的任务分层、道路导航、停车停留与乘客上下车思路，适配当前武汉运行系统，未搬入其英国交通规则、账户或后端。

- `taxi-routing.js`使用武汉既有节点身份、折线和单行方向进行道路路径搜索。找不到路径返回不可达；不合并“靠得很近”的路口，也不拿穿江直线代替道路。
- `taxi-network.js`提供有名字的停靠点与三条订单，排除步行边、架空边及试验区外道路。出现偏航时从当前道路位置重新规划；重新规划不改变角色位置。
- `taxi-trip.js`是独立状态机，处理主动接受、停车、上下车、里程计费及取消。没有强制接客或强制结算的录制接口。
- `taxi-fare.js`复用现有PersonCrowd/PersonRig显示乘客，提供简体中文任务界面和路面导航带；小地图和全屏地图使用相同路线。
- 计费为玩法中的虚拟数值：起步8元，加实际公里数与时间；不代表武汉现实运价。收入与当班统计仅在当前页面会话保留，无账号、真实支付或排行榜。

当前没有复杂评分、紧迫倒计时、任意地址派单、智能驾驶和完整网约车经营系统。普通交通与玩家碰撞仍然生效，导航可行不代表所有路况都无碰撞或无需玩家调整。

## 验证与录像

新增规则测试覆盖单行方向、不连通路段、道路距离、不同高程、停靠保持、移动中止上下车、模式切换、传送与不重复支付。三条订单均通过浏览器内实际控制器和交通物理验证：从普通开始/接受按钮启动，用油门、方向与刹车输入行驶，依次完成上车、送达、下车与结算。

复现命令：启动本机服务后，运行`node tools/taxi-session.mjs --verify --url http://127.0.0.1:4802/`。如果Playwright在独立目录安装，传`--playwright /path/to/playwright/index.mjs`。验证可跳过每帧绘制以加快车辆物理回归；各状态检查帧会单独绘制。正常录像不带`--verify`，每帧等待GPU完成并保存为1080p30 MP4。录制位置只在接单前准备，途中无强制状态切换或传送完成。

完整原片与25—40秒的剪辑节选保存在用户指定的外部素材目录，视频不纳入Git。节选应说明经过剪辑，不能把不动的状态演示或跳切称为完整连续驾驶证明。与原0.8.5视频素材的功能差异在脚本里另作更新。

本轮实录：江汉关附近至巴公房子附近，完整109秒；车上计程约1,053米、91.77秒，虚拟收入10.6元，只结算一次，浏览器错误为空。完整片含接单前后等待及接客部分，故不等于车上计时。`tools/build-taxi-demo.py /path/to/taxi-materials`依据录制状态时间从同一原片剪出约31秒节选，并输出预览和抽检帧。三条路线的物理验证分别完成约1,053、791、1,280米，虚拟收入10.6、10.0、11.2元。
