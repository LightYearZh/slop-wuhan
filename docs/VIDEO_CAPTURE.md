# 视频素材录制工作流

为约7分钟的项目介绍准备素材。录制使用本地0.8.5真实场景，分为镜头编排的观景画面、带界面的操作演示与保留物理的连续驾驶。

## 画面

工具：`tools/capture-video.mjs`、镜头表：`tools/video-shots.mjs`。需要已安装的Playwright、桌面Chrome、FFmpeg。先启动本机开发服务，再运行录制工具：

```sh
npm run dev -- --port 4801
node tools/capture-video.mjs --url http://127.0.0.1:4801/ --output output/video
```

若Playwright安装在独立工具目录，可传入 `--playwright /path/to/playwright/index.mjs`。`--only W03A,W06`只录指定镜头；`--sample`输出首个指定镜头的2秒样片。输出中已有同名正式MP4会跳过，重录应使用新目录或先移走旧片，避免覆盖已选素材。

工具仅拦截**录制浏览器**取得的本机入口模块，在内存加入逐帧控制；不修改正式应用的启动、模型、地理数据或碰撞规则，不需要将录制钩子部署到公网。相机、时间、位置、方式均由镜头表确定。车辆路线通过油门与转向输入推进，仍受原有碰撞、道路和水域约束，不把强制移动角色的动画冒充实际通行。

每次导出逐帧推进1/30秒的游戏模拟，等GPU完成再截图并编码，输出1920×1080、30fps、H.264 MP4。观景画面隐藏操作界面，保留数据归属；操作段保留真实界面。画面没有同步音轨。HUD帧率受导出时间步控制，不能拿它作为正常游玩的设备性能测试结果。

每段保留起、中、末检查帧、每秒位置轨迹与运行错误记录。城市动态及着色器仍有各自的种子和时钟，不能把此工具说成逐像素完全可复现的全场景离线渲染器。逐帧输出避免录制电脑的实时抓屏掉帧影响成片时序，导出耗时不等于视频时长。

## 游戏原声

```sh
node tools/capture-game-audio.mjs --url http://127.0.0.1:4801/ --output output/video/audio
```

直接录制游戏自身Web Audio主混音，不访问麦克风或其他应用的声音。输出城市街道与步行、出租车启动加速与滑行、直升机飞行三段WAV（48kHz/24bit），并保留原始Opus WebM。原声为单独实时录制，可作环境底声或效果参考，**不与逐帧视频逐镜同步**。

## 抽检与交付

```sh
python3 tools/video-catalog.py output/video
```

需Pillow。工具使用FFprobe核对规格、时长，实际解码每段起、中、末帧，检查运行错误并统计轨迹；生成`素材清单.csv`、`素材总览.jpg`、`素材预览.html`与`验收.json`。仍需目视检查镜头是否遮挡、穿模或偏离主题，并按轨迹确认连续通行；视频可正常编码不等于路线已走通。

高空全景可见矩形地图边界，适合交代约8×6公里覆盖范围；较低的全景更适合开头。隧道完整录制与剪辑节选分开保存，不把入口与出口跳剪伪装成连续穿越。不同镜头之间的正常传送和切换只作为单独素材准备，不编造成一镜到底。

正式素材保存在用户指定的外部目录，不纳入Git，不随站点部署。口述、配音、成片剪辑与二维码另行制作；素材录完不代表视频已经发布。

交付目录包含`先看这里-素材说明.md`、`总素材预览.html`、`总素材清单.csv`和各批检查帧。MP4为无声画面，独立WAV不能称为逐镜同步原声；这些文件用于后续剪辑，并未制作或发布完整视频。
